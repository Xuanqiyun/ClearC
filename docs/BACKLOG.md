# 改进清单

来源：2026-10-24 的三份评审（安全和运维、用户体验、架构），基于 3.5.2。一条一条做。

做法：
1. 每条先写一个会失败的测试，再改到它通过。
2. 一条一个提交，提交说明里写上编号。
3. 做完在「状态」一栏写上版本号。

先后顺序：先做 P0，再做 P1、P2。同一优先级里，按「先后」一栏，数字小的先做。

## 运维（OPS）
