# For people and AI assistants taking over this repository

ClearC (腾挪 ClearC) is a Windows C: drive cleanup tool: PowerShell 5.1 + WPF + embedded C#, packaged as a single exe that needs no installation. Read this page first, then open only the files it points to as you need them. Don't read the 23,000-line script from top to bottom.

## Where the code is

- `src/CleanC-UI.ps1`: the single script that actually runs; it is what the exe embeds.
- `src/parts/`: the same content split into modules for reading and review (`order.txt` is the join order, `README.md` says what each file does). The two must match: after editing the single file, run `python3 build/split.py`; after editing the parts, run `pwsh build/merge.ps1`.
- Main modules: `engine/Engine.ps1` (background work: the folder catalog, deleting, moving, scanning, repairs), `ui/*.ps1` (each page's interaction), `ui/main.xaml` (the window and the Chinese help), `cs/*.cs` (C#: reading the NTFS file table, finding duplicates, folder statistics, color conversion), `i18n/en.tsv` (the English translation table).
- The help page's content and layout are generated by `tools/help/`. Don't edit the help in the XAML by hand: edit `help_zh.py`, `help_en.py` or `helpxaml.py`, then run `python3 tools/help/regen.py`.
- `docs/SAFETY.md`: the safety rules, the guard on every delete and move path, the defect list, and the tests that enforce them. Read it before changing any code that deletes, moves or changes system settings.
- `docs/BACKLOG.md`: open and finished improvements, by priority, each with its status.

## Common commands (from the repository root)

- Local checks: `bash tools/check.sh`. It prints one line per check:
  - split/merge in sync
  - syntax
  - untranslated text
  - Chinese left over in the English UI
  - the three test suites in `tests/`
  - a C# 5 compile
  - dark-mode contrast
  `PWSH` points to pwsh; the C# 5 compile needs `build/refasm`, see the top of `build/build-roslyn.ps1`.
- Build the exe: `pwsh build/build-roslyn.ps1 -Out out/ClearC-vX.exe`. This works on Linux too.
- Wait for CI: `bash tools/ci-wait.sh <sha>`. GitHub Actions runs on Linux and on real Windows; on Windows it also runs the UI self-test three times (`src/parts/ui/95-ui-test.ps1`) and the real-disk self-check.

## Conventions for changing code

- Edit the single file with `tools/ed.py`, which replaces exact original text and stops if the match count is wrong. The file is CRLF with a BOM.
- Language:
  - Commit messages, documentation (`README.md`, `CHANGELOG.md`, `docs/`, this file) and pull requests: English. Commit messages start with one line that says what changed; add a blank line and details when needed.
  - `README.zh-CN.md` and `CHANGELOG.zh-CN.md` are the Chinese versions for users; keep them in step with the English ones.
  - Code comments and UI text stay in Chinese.
- UI text is written in Chinese inside `T '…'`; add the English to the translation table with `python3 tools/i18n_add.py '中文' 'English'`. The Chinese text is the translation key, so if you reword the Chinese, update its English entry too.
- C# uses C# 5 syntax only, because the csc that ships with Windows only supports C# 5. `$rowCode` and `$dupCode` are compiled into the exe; `$script:photoCode` references WPF and is compiled at run time.
- The main window XAML is in `[xml]$xaml = @"…"@`, a string that expands variables: don't write `$` in the XAML.
- Background jobs: register them next to the code that starts them with `Register-BgJob 'name'` (whether it can be cancelled, whether it is read-only and how it finishes are all declared there), and start them with `Use-BgJob 'name'`. Don't assign `$sync.Mode` directly.
- Functions that are only called at run time can be defined after the code that calls them; code that runs at load time can only use functions already defined. For example, `Register-BgJob`, which registers background jobs, is defined halfway through `ui/10-window.ps1`, so registrations must come after it.
- PowerShell pitfalls:
  - `$x = if (…) { $list }` unrolls the list; assign it directly instead;
  - `@(f)`: when f returns `,$list`, the result is wrapped as a single element;
  - don't name a switch parameter `-Quiet`; the safety tests count how often it appears.

## Rules that must not be broken (details in docs/SAFETY.md, enforced by tests)

- Nothing in the personal folders on C: is deleted; chat data can only be moved, never deleted; deletes never follow links; system locations, software install folders, the Recycle Bin and restore points can't be deleted.
- Deletes must be confirmed by the user first. Deleting user files may only go through `Invoke-SafeRemove`: it does every check (personal folders, system locations, links, whether the Recycle Bin can hold it), verifies the result and writes the activity log. Any new delete call elsewhere makes the safety tests fail (section 14 counts them with the syntax tree).
- No ending processes, with two exceptions: the programs listed in the move confirmation, and a stuck, windowless copy of ClearC itself (ended only after the user clicks Yes). No registry cleaning, no deleting restore points.
- Scheduled tasks are off by default, run only as the current user, never as SYSTEM and never at startup.
- Code changed for speed may only read and measure; it must not change what gets deleted.
- Source locks: the location and number of every delete call (found by `tests/DeleteSites.ps1`), ending processes, scheduled tasks, `pnputil` and restore-point calls (found with the syntax tree by `tests/CallSites.ps1`), the number of `rd /s`, and the repair steps that can run without confirmation are all counted by tests. To change these numbers, first write down in SAFETY.md why the change is safe.

## Releasing

The version number is changed in one place only: `$script:AppVersion` (the build script derives the exe's file version from it and fills in the build date). Add a section for the version to `CHANGELOG.md` (English) and `CHANGELOG.zh-CN.md` (Chinese); the checks verify both. Commit on a feature branch. After CI passes, run `git checkout main && git merge --ff-only <branch> && git push origin main`, build the exe, and write the release notes in `docs/releases/vX.md` with the exe's SHA256.
CI artifacts and logs can't be downloaded; only the annotations are visible, at most 10 per step. Pushing tags is rejected; the maintainer publishes Releases by hand.
The exe is not signed. Before a release, put it in a zip with the password `infected` and submit it to Microsoft for review (Defender flags new exes as trojans); `docs/RELEASING.md` describes each step. Don't add code to the launcher that is typical of attack tools, such as probing the PowerShell language mode first.
