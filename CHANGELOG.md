# Changelog

## 3.6.3
- **ClearC not opening on double-click**: after the window closed, unfinished background reads (disk health, pre-reading the file table) sometimes kept the program running in the background with no window, and the next double-click assumed a copy was already open and quit. Now closing the window ends the whole program. If a copy is still stuck in the background, double-clicking explains this and asks whether to end it and open again; clicking "Yes" is enough, with no need for Task Manager. If that copy is in the middle of a delete or move, ClearC warns what stopping halfway means and defaults to "No".

## 3.6.2
- 3.6.1 was reported by Windows Defender as Trojan:Win32/Bearfoos.B!ml on download (the !ml at the end means a machine-learning heuristic, not a match on specific malicious code). The launcher no longer probes the PowerShell language mode itself (attack tools often do this); the script's first line checks it instead, and a locked-down company PC still gets the explanation. The exe is not code-signed, so a new version may still be flagged right after release; every version is submitted to Microsoft for review before it is published.

## 3.6.1
- **Space map: each drive's capacity is shown once**. Previously the "used / total" of C: and D: appeared in the drive picker, on the drive card and again in the overview below, sometimes 0.01 GB apart. Now the drive picker shows only the drive letter; the card shows "used / total · percentage" on the left and the free space on the right; the overview below only says how the used space splits into system and apps, personal files, cleanable caches and other, and the parts add up exactly to the used space (hard links counted once in each of several folders are scaled back proportionally). The overview shows the total only when the disk cards are turned off in Settings. At the top level of a drive, the line above the list no longer shows a "this level in total" figure that didn't match the used space.
- Every page reads "used" and "free" the same way, so the same drive shows the same numbers everywhere. The hint under the move target no longer repeats the free space shown in the drop-down.
- **Line and letter spacing**: wrapping text gets about 1.5× line spacing for its font size (19 for 12 pt, 21 for 13 pt, 22 for 14 pt), so several lines of Chinese no longer crowd together; single-line labels are unchanged and still line up with the buttons next to them. On screens scaled to 125% or more, text uses Ideal glyph layout, so the spacing between characters no longer varies.

## 3.6
Built item by item from three reviews (safety and operations, user experience, architecture); the list and the test for each item are in docs/BACKLOG.md.
- **Safer deletes**: every place that deletes user files goes through one entry point, which checks personal folders, system locations, links and whether the Recycle Bin can hold the files before deleting, then verifies the result and writes the activity log; deleting duplicates is logged file by file. Folders that hold passwords, certificates and keys are blocked for every account on the PC. The settings file is written to a temporary file first and then swapped in, and nothing is deleted if it can't be read.
- **One thing at a time**: only one window can be open; deletes, moves and settings changes hold a lock, and a scheduled automatic cleanup that runs into it skips that run.
- **Moves can be cleaned up after a power cut**: every finished step is recorded, so the next start says where it stopped and lets you finish or undo it; after copying, the file count and size are checked and not a single file may differ. Moved chat data, Desktop and Documents keep their original permissions, so other accounts on the PC can't open them; earlier moves can be fixed in one click. When C: is encrypted and the target drive isn't, the confirmation says so.
- **One-click cleanup only deletes, never moves**: chat data has its own card on the cleanup page and is moved only when you click it. On a PC with only C:, move items are skipped by default; USB drives are never picked as the move target automatically, and choosing one by hand asks again; "Moved folders" appears once something has been moved, and broken links are reported.
- **First start**: after you agree to the notice, a scan runs automatically and the result is one card with one main button. The cleanup page's tabs show how many items are selected, a whole group can be skipped with "Skip all in this group", and totals are split into delete and move; several confirmation dialogs became one, the main button says exactly what it will do, and permanent delete is red.
- **Easier to read and usable from the keyboard**: description text has a contrast of at least 4.5:1 and a 12 pt minimum; keyboard focus is outlined, screen readers can read the names of icon buttons; help only describes the features of the current mode; easily misread names such as "careful cleanup" and "needs confirmation" were renamed.
- **Less waiting, less guessing**: "Opening" appears right after the administrator password is entered; the help page loads the first time it is opened; the photo fingerprint code is compiled only when used. After a theme or language change restarts the window, it returns to the same page and scan results. Errors first say what happened and what to do next, with Windows' original message after that. The app list shows each app's own icon.
- **Operations**: ClearC speaks up when C: is nearly full or the activity log can't be written; the PC doesn't sleep during long operations, and moving a large folder on battery warns first; when elevated with a different administrator account, it first explains which account cleanup and moves will act on; takeown and icacls no longer depend on the system language; Settings has a new "What ClearC changed" page that shows the current state of each change and how to undo it, and a restore point can be created before system settings are changed; the run log moved to %LOCALAPPDATA%\CleanC\logs and is rotated; the restricted language mode on company PCs gets a one-line explanation; "Reminders" shows the task's last and next run time and result.
- **Downloaded files can be checked**: "Feedback and updates" shows the SHA256 of the exe on this PC for comparison with the release page; exporting a diagnostics package lists what's in it first and can leave out memory dumps. Scheduled tasks now run the copy placed in Program Files\ClearC (only administrators can change it); the launcher no longer loads assemblies based on environment variables; system program paths are no longer taken from environment variables; download pages and the run log are opened through File Explorer, without administrator rights.
- Internals and tests: background jobs and cleanup actions use stable identifiers; errors in the background are written to the run log; statistics no longer share static fields; the version number exists in one place only; the path rules and the move-progress state machine started moving into C#. The safety tests' source locks use the syntax tree; the Windows test machine mounts a virtual disk, really moves a folder there and back, and simulates two power cuts in the middle.

## 3.5
- **The help page has a contents list on the left**: like the Settings page, the left side lists every item grouped under "Start", "Cleanup", "Analysis", "Management" and "Other" (quick start, each feature, the FAQ, feedback and updates); click an item and only that item is shown on the right, with "Previous" and "Next" below, and the last item viewed is remembered; "Feedback" at the bottom left opens "Feedback and updates" directly, and clicking "Help" again returns to the item you were reading.
- **Faster scans** (measured on GitHub's Windows test machine, before and after on the same machine):
  - Clean up C:: only the items listed in the current mode are measured; the few that wait for Windows to answer (orphaned Windows Installer packages, old driver packages in the driver store, the Delivery Optimization cache, broken shortcuts) are asked in a separate background job at the same time while the file table is read and the rest measured; installer package registrations are queried in one go (the same locations and calls as the old one-by-one queries, and a test verifies both give exactly the same result); the Recycle Bin size is asked from Windows directly; short-name paths such as %TEMP% are converted to long paths before the file table lookup; whether a parent folder is a link is checked only once (deletes still check every time). Developer and IT mode went from 14.7 seconds to about 3 seconds (with the file table already in memory and the driver packages asked once), and the first Home user scan from about 18 seconds to about 9 (a cold start on this test machine, where reading the file table took most of the time; normally the file table has been read in the background a few seconds after opening).
  - A few seconds after ClearC opens, when idle, the C: file table is read into memory in the background (read only); after that the cleanup scan, Apps, moving and the space map only re-read the changed parts from the change journal.
  - Context menu extensions: read straight from the registry, from 6.0 seconds to 0.4.
  - System health: hardware, startup, blue screens, events and the clock are read at the same time, from 9.8 seconds to 4.0.
  - "Can be moved": installed apps and Store chat apps are read at the same time; whether an app comes with system services and drivers is decided by reading the program paths registered in the registry instead of waiting for WMI (which sometimes takes nearly 10 seconds on the test machine), from 4.6 seconds to 1.8.
  - Leftover folders: last changes and sizes come straight from the C: file table instead of measuring folder by folder; apps installed on other drives and moved folders read that drive's file table once; Store app names are read straight from the manifest in the install folder.
  - Duplicates: when looking for files of 1 MB or more on an NTFS drive, files are listed straight from the file table (with the same rules as reading folder by folder: the same system, software and development folders are skipped, links and cloud folders are not entered, and system, offline and cloud placeholder files are not compared), with no more reading folder by folder: listing all of Program Files folder by folder took 2 to 6 minutes on the test machine, and less than a second with the file table in memory; the file table now also records each file's attributes. Before fingerprints are computed, file sizes are checked against the listing.
  - Old driver packages in the driver store: DISM isn't asked again within the same session if the driver packages haven't changed; Developer and IT mode asks in advance while idle.
  - How long each item took during a scan is written to the log, so slow spots are easy to find later.
- Tests: the UI self-test checks that the services and drivers read from the registry are no fewer than WMI's; in the speed test, the same duplicate search listed once from the file table must give exactly the same result as listing folder by folder (7 minutes folder by folder on the test machine, under a second from the file table); the UI self-test covers the help page's contents (only the selected item is shown, previous and next, Feedback and returning to the item, every item has content); the first Windows test run measures the time of each kind of scan (the lines starting with timing in the report); querying installer registrations in one go is checked against one-by-one queries; the safety rule tests were updated (orphaned installer packages aren't judged if the interface can't be read).

## 3.2
- **Diagnoses come with what to do**: under each finding there are two parts. "Fix as suggested" does the steps ClearC can do directly in one go: it lists what it will do first and asks once, and everything can be undone (drive dropping out: turn off drive and PCIe power saving and Fast Startup; wrong time: open Date and Time; system files: repair system files; memory: memory diagnostics), and afterwards it says what was done and what is left. "Things to do yourself" lists, in order, what ClearC can't do: backups, updating the BIOS / storage driver / SSD firmware (with how old this PC's current versions and dates are), the vendor's hardware diagnostics (F12 into ePSA on Dell), reseating the drive, and only as the last step replacing it. The report and the summary.txt in the diagnostics package also list "ClearC can do directly" and "you need to do yourself".
- **Vendor driver download pages**: opens the BIOS, driver and firmware download page for the vendor and model, straight to the service tag on Dell; the link is copied at the same time, so a PC without internet access can hand it to another PC for downloading.
- **Switching to Windows' own disk driver** (when a drive on Intel RST / RAID On keeps dropping out): first checks for you whether there is a single drive, whether a RAID array exists and whether BitLocker is on, then lists the steps for switching to AHCI in the BIOS and how to switch back; this needs the BIOS, and ClearC doesn't change it for you.
- **More accurate diagnosis**: the number of blue screens is counted from Windows' crash records (WER 1001), so none are missed even when only the last few minidumps are kept; ClearC reads this PC's vendor, model, BIOS version and date, service tag, storage controller driver version and date, the system drive's model and firmware, and BitLocker; disk read/write errors are attributed to the specific disk by disk number, so errors on USB sticks and external drives are no longer blamed on the system drive; crashes where not even a dump was written are counted separately; a system time earlier than ClearC's release date (when the clock has been wrong ever since Windows was installed, file times are wrong too, which couldn't be detected before) and a time service that never manages to sync (name resolution failing = no internet access) are both reported.
- Repairing system files: when there is no internet access, DISM reports an error; the window now says that this doesn't matter and that the sfc run that follows still works. "Date and time" now opens the Control Panel's Date and Time, so it can be set by hand on PCs without internet access.
- The systeminfo and driverquery output in the diagnostics package is read with the system locale's code page, so it is no longer garbled on Chinese Windows; drive temperatures reported as 0 or 1 °C (controllers such as RST report nonsense) are treated as unreadable; blank lines no longer appear among recently installed drivers.
- Tests: parsing WER records, USB errors not counted against the system drive, a clock earlier than the release date, the Dell download page, the fixes in the report; new safety rule tests: "Fix as suggested only uses steps that can be undone and delete nothing, after one confirmation" and "the disk driver guide doesn't run bcdedit for you"; the checks report a release date that hasn't changed for a year; the UI self-test covers Fix as suggested asking first, the vendor download page and the disk driver guide.

## 3.1
- **Blue-screen diagnosis fixed and explained in plain words**: the dump parser had been reading the driver table wrongly (each entry is 0x90 bytes and the name is a full path), so "probable driver" and "drivers on the stack" were both wrong for real dumps; it has now been checked against real Win10 1903 dumps. It newly reads the disk-read status code (0xC000000E with 0x7A means the drive dropped out), the process at the time of the crash (with 0xEF, the critical process that exited) and who made the drivers on the stack; 0x50 now looks at parameter 3, and 0x116 at parameter 2; when only Windows' own drivers are on the stack, no driver is wrongly blamed; for 0x7A, the driver that owns the page that couldn't be read back was just unlucky and isn't named. Each blue screen gets one sentence saying what the error is and its common causes.
- **Diagnosis**: looks at several blue screens, the event logs, drive health, the system clock and the Windows version together, and gives a few findings with matching fix buttons: an unstable drive or drive connection (disk-read failures + a system process exiting repeatedly + disk errors, also recognizing the Intel RST storage driver), the same third-party driver blamed repeatedly (with different advice for graphics, network, security software, anti-cheat and storage), graphics, memory, hardware errors, sleep and wake, repeated unexpected shutdowns, a wrong system time (files written by Windows itself dated later than "now"), and a Windows version that is too old. "Copy report" copies it as text; "Export diagnostics package" zips the dumps, the last 30 days of system and application logs, systeminfo, the driver list, drive information and the report, without overwriting existing files.
- **Common fixes**: the fixes most often recommended on forums that really work, listed by problem (blue screens and freezes, drives dropping out and stutter, damaged system files, failing Windows Update, no network, wrong time, shutdown turning into restart and failed wake, no sound, icons and the Store, slow startup, sending the information to someone else), with each step marked view only / makes changes / needs restart. They are all commands that come with Windows, run in a visible terminal and recorded in the activity log; anything that changes something explains first and asks for confirmation; the Windows Update components are renamed, keeping the old ones, not deleted; "Turn off drive power saving" (PCIe link, AHCI link, turning off the disk) saves the original values first, and "Restore drive power saving" puts them back exactly; Fast Startup can be turned back on at any time. Repairing system files now runs DISM /RestoreHealth first and then sfc /scannow, and is available in Home user mode too.
- **System health is now tabs**: a row of tabs next to the title (Hardware, Boot time, Blue screens and crashes, Common fixes, Activity monitor, Windows events); click one and only that one is shown, each scrolling on its own; the last tab viewed is remembered. Home user mode can see Blue screens and crashes and Common fixes.
- **Clean up C:**: after a scan, double-click a row to open the folder it is in, or right-click for "Open all locations" and "Copy path", which makes it easy to copy out logs and dumps for analysis; for items handled by Windows commands, such as the Recycle Bin, Delivery Optimization cache, search index, Installer, driver store, event logs and WinSxS, this opens the place where Windows keeps them.
- **Space map**: clicking a drive card at the top selects and scans that drive and shows its details below; the selected card is outlined in blue.
- Clicking the mode label at the bottom left takes you to Settings, where the "Mode" card lights up briefly to show where to change it.
- Tests: assembled dumps test the 0x90 driver table, full paths, the 0x7A status code, the 0xEF process, and 0x50 naming no driver when only Microsoft drivers are present; several combinations of diagnosis findings; new safety rule test §7f (repair commands delete no files, end no processes and create no scheduled tasks, everything that changes something asks first, the update components are only renamed and only the services it stopped are restarted, drive power saving is saved first, the diagnostics package never overwrites files); the UI self-test covers the tabs, repair steps asking first, opening folders from the cleanup page, scanning from a drive card and the mode card lighting up.

## 3.0
- **Data-safety audit**: every execution path of cleanup, moving, duplicates, the space map, Apps and Save space was checked one by one, and 29 problems that could lose data were fixed (plus 9 that need rare conditions, fixed at the same time). The most important: deleting Windows.old could follow links inside it and delete the current system's AppData; two paths to the same file were treated as duplicates, so the only copy got deleted; "move to Recycle Bin" became a permanent delete when the Recycle Bin couldn't hold the files, was turned off or was on a network location; after the cleanup list changed following a scan, what ran wasn't the item that was confirmed; one-click cleanup ticked "needs confirmation" items; chat data inside a OneDrive-synced folder was treated by OneDrive as deleted after a move; moving back to C: deleted the folder that a user's own link pointed to; after an app was moved to D:, cleanup followed the link and deleted caches on D:; duplicates could delete WeChat data that had been moved to D:; moving the temp folder to D: took over the user's own D:\Temp and emptied it later. The full list, the problems that could be postponed and the reasons are in docs/SAFETY.md.
- **Safety rule tests** (tests/Safety.Tests.ps1): run on every push on Linux and Windows (PowerShell 5.1). Some build fake personal folders, links and hard links in a temporary folder and really try to delete them; others count the dangerous calls in the source (`rd /s`, Recycle Bin calls, `pnputil`, scheduled-task identity), and break if something goes wrong.
- **Three modes**: Home user, Engineer, and Developer and IT. Double-clicking opens in Home user mode by default, with no dialog; change it at the top of "Settings" at any time, and the current mode is shown under the version number at the bottom left. Changing modes only changes what is shown and loses no settings or records.
- **System health** page (view only, changes nothing): hardware cards (CPU load / clock speed / throttling judged from performance counters / ACPI temperature; memory used / committed / hard faults / WHEA memory errors; each drive's SMART health / temperature / wear / read errors / power-on time; battery design capacity / full-charge capacity / cycle count; GPU usage / video memory / driver; Windows uptime / pending restart / recent updates / devices with problems), saying plainly when something can't be read instead of passing off an estimate; boot time and the programs that slow down startup (Diagnostics-Performance log events 100 / 101); blue screens and crashes: ClearC parses minidumps itself (DUMP_HEADER64 + TRIAGE_DUMP64: bug check code, parameters, driver table, which driver the faulting address falls in, drivers seen on the stack), plus the last 30 days of unexpected shutdowns / crash records / WHEA / disk / NTFS events and recently installed drivers, with sfc / DISM split into "check (view only)" and "repair (makes changes, asks first)"; activity monitor: while open, samples every 3 seconds and shows CPU, memory, write speed, written during this monitoring and written since startup, merged by program, with no service installed; Windows events: critical and error events of the last 7 days grouped by source.
- **Space map**: an overview at the top (used / total, percentage, and a segmented bar of system and apps, personal files, cleanable caches, other and free); the treemap and the list are shown together and linked (clicking a tile selects its row, Ctrl selects several, selected rows are outlined on the treemap, double-click goes in); "By type" sorts every file on the drive into ten groups by extension (the file table counts them too, not only files of 1 MB or more), and double-clicking a group goes to "Find files"; "Find files" shows up to 1,000 files, sorted by size or modified time, filtered by owner, with the compressed size noted for NTFS-compressed files; "Recent changes" reads the change journal (USN) and lists the folders where files were created or rewritten most in the last 1 / 3 / 7 / 30 days; "Since last scan" keeps dated snapshots (at most 40 per drive), lets you compare with 1 / 3 / 7 / 30 days ago or the earliest, and says in one sentence how much the used space grew and where (Docker data, WSL distributions, browser caches, Windows Update, a particular folder…).
- **Tiered cleanup**: safe cleanup, careful cleanup (browser caches, thumbnails, shaders, download caches: also cleaned by default, but in their own group and listed separately before running), needs confirmation (skipped by default) and protected (never touched); in the confirmation dialog, "View file list" lists the 60 largest items and saves the full list as text; "Move to the Recycle Bin when deleting" in Settings (sent in batches, with Windows asking about ones that are too big; automatic cleanup is unaffected); the activity log records the free space before and after each item; "needs confirmation" gains "old driver packages in the driver store" (Get-WindowsDriver finds old packages of the same driver with newer versions, deleted with pnputil without /force, and boot-critical ones untouched; Developer and IT).
- **Duplicates**: "Similar photos" (9×8 grayscale dHash: nearly identical 4 bits / similar 8 bits / roughly similar 12 bits, sorted by resolution with the dimensions and bit difference shown, never ticked automatically, and only sent to the Recycle Bin or archived, never permanently deleted or merged); new keep rules "keep the one in a given folder" and "keep the one with the shortest path"; "Archive checked…" doesn't delete: it moves the files under a chosen folder, arranged by drive letter and original path.

## 2.5
- Renamed to "**腾挪 ClearC**" (formerly "C盘清理工具"): clearing out and moving away what takes space to make room on C:. Settings, the activity log and reminders carry over with nothing to set up again.
- **Much faster scans**: NTFS drives (C: almost always is) are read straight from the file table (MFT) on the drive instead of looking at folders one by one, so hundreds of thousands to millions of files are usually read in a few seconds to a dozen or so. The result is checked against a direct folder listing; if they don't match or the table can't be read (not NTFS, not enough rights and so on), ClearC falls back to scanning folder by folder automatically.
- **Scanning again in the same session only looks at changes**: following Windows' change journal (USN), only the changed part is read again. Nothing is cached on C: after ClearC closes.
- **Read once, shared by every page**: "Clean up C:", "Moved folders" and "Apps" also read the C: file table once when measuring sizes, so each folder's size can be looked up directly. These numbers are only for display and estimates; when actually deleting or moving, every item is measured and checked again.
- **Folder-by-folder scanning is faster too**: directory entries are read in large batches and counted on several threads (more threads for SSDs, fewer for hard disks). Listing files for the duplicate search works the same way.
- Reading the file table reveals folders that folder-by-folder scanning can't enter (such as System Volume Information), so "Since last scan" warns when the two scans used different methods, so that this part isn't mistaken for growth.
